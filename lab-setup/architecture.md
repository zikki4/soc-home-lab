# Архитектура стенда

Учебный стенд для отработки работы с SIEM: проведение атак на машину-жертву
и разбор инцидентов по логам.

## Машины

- **Kali** — атакующая машина, источник атак
- **Ubuntu** — жертва/цель: на ней установлен агент Wazuh, за ней ведётся наблюдение
- **Ubuntu-wazuh** — SIEM-сервер: собирает события и анализирует их

## Сеть
                    ИНТЕРНЕТ
                       │
                       │ NAT (обновления, агенты)
                       │
              ┌────────┴────────┐
              │  Ubuntu-wazuh   │
              │   SIEM-сервер   │
              │ (сбор, анализ)  │
              └────────┬────────┘
                       │
        ═══════════════╪═══════════════  host-only (изолированная сеть)
              │                 │
     ┌────────┴────────┐  ┌─────┴──────────┐
     │      Kali       │  │     Ubuntu     │
     │   атакующая     │──▶│  жертва/цель  │
     │                 │атака│  (агент Wazuh)│
     └─────────────────┘  └─────┬──────────┘
                                │
                                │ агент шлёт логи
                                ▼
                          (на Ubuntu-wazuh)

- Все три машины объединены сетью **host-only**. Это изолирует стенд от
  реальной сети — атаки не выходят наружу.
- На машине Ubuntu-wazuh дополнительный адаптер **NAT** — для доступа в
  интернет (обновления, загрузка агентов). Вся работа с SIEM при этом
  идёт по host-only.

## Как события попадают в SIEM

Агент на жертве читает логи → отправляет на сервер по host-only →
сервер обрабатывает → событие видно в дашборде.
