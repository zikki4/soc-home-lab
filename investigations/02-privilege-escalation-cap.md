# Разбор атаки: цепочка компрометации (HTB Cap) и её детектирование

**Тип:** ретроспективный анализ детектируемости — разбор шагов атаки и того,
как каждый из них можно обнаружить в SIEM / логах. Атака выполнена на учебной
машине HTB Cap; детект описан гипотетически, как если бы машина была под
мониторингом Wazuh.

## Ход атаки

1. **Разведка:** ping + сканирование портов, обнаружен открытый порт 80
2. **Доступ к данным:** на веб-сайте (порт 80) уязвимость IDOR — подмена id
   в URL даёт доступ к данным других пользователей, получен файл pcap
3. **Кража учётных данных:** в pcap через tcpdump найдены логин и пароль
   (учётные данные передавались в незашифрованном трафике)
4. **Первичный доступ:** вход по SSH с найденными учётными данными
5. **Разведка на хосте:** поиск путей повышения привилегий
6. **Повышение привилегий:** обнаружен `/usr/bin/python3.8` с capability
   `cap_setuid`; через него получен root

## Детектирование по шагам

| Шаг атаки | След | Как обнаружить | MITRE |
|---|---|---|---|
| Скан портов | Множество портов с одного IP за короткое время | Правило SIEM на port scan; в трафике — серия SYN без ответа | T1046 |
| IDOR на сайте | Аномальные запросы с перебором id в URL | Веб-логи: один пользователь обращается к чужим id | T1190 |
| Пароль в pcap | Учётные данные в открытом трафике | Сетевой мониторинг незашифрованных протоколов | T1040 |
| Вход по SSH | Успешный вход — но с IP, который ранее сканировал порты | Корреляция со сканом + вход с нового для профиля IP (UEBA) | T1078 |
| Разведка (getcap) | Команда `getcap` в журнале выполнения | auditd: execve с подозрительной командой | T1548 |
| python setuid → root | `execve` python с `os.setuid(0)`; несоответствие auid и uid | auditd: `auid=nathan`, `uid=0` — root-действие из-под обычного юзера | T1548 |

## Ключевые выводы

- **Тихий шаг ловится в связке с шумным.** Вход по SSH сам по себе легитимен
  (верный пароль), но в цепочке со сканом портов с того же IP становится
  явно подозрительным. Аналитик видит цепочку событий, а не отдельные факты.
- **`auid` — ключ к детекту повышения привилегий.** Поле loginuid не меняется
  при смене UID, поэтому связка `auid` обычного пользователя + `uid=0`
  однозначно указывает на повышение привилегий.
- **Учётные данные в открытом трафике — корень компрометации.** Пароль,
  переданный незашифрованно, обесценил всю дальнейшую защиту.
