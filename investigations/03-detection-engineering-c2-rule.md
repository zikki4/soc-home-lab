# Detection Engineering: правило обнаружения reverse shell (C2 на порту 4444)

**Тип:** разработка правила детектирования (detection engineering) в Wazuh.
Обнаружение пробела в детекте и написание кастомного правила для его закрытия.

## Проблема

Reverse shell (meterpreter), устанавливающий C2-соединение на порт 4444,
не создавал алерта в SIEM. Событие сетевого соединения фиксировалось Sysmon
(Event ID 3) и доходило до Wazuh, но в дашборде не отображалось как угроза —
реальный C2-канал проходил мимо аналитика.

## Анализ причины

Штатное правило Wazuh для сетевых событий Sysmon (rule 92101,
«Powershell process communicating over TCP») обрабатывало это соединение,
но имело `level="0"` — то есть намеренно не создавало алерт. Отдельного
правила под порт 4444 в штатном наборе не было. В результате соединение
на классический reverse-shell порт распознавалось, но «молчало».

Ключевое различие: level 0 — это не «нет правила», а «правило есть,
но заглушено». Событие обработано, но не поднято как тревога.

## Решение

Создано кастомное правило в `/var/ossec/etc/rules/local_rules.xml`:

- **id:** 100002 (кастомный диапазон 100000+)
- **привязка:** группа `sysmon_event3` (все сетевые события Sysmon)
- **условие:** `win.eventdata.destinationPort` = 4444
- **уровень:** level 12 (высокий)
- **MITRE:** T1071 (Command and Control)

Правило срабатывает поверх штатного и поднимает соединение на 4444
до high-алерта.

## Проверка

1. Синтаксис правил проверен через `wazuh-logtest` до перезапуска
   (валиден — manager стартует).
2. Перезапущен wazuh-manager.
3. Проведён тест: сгенерирован reverse shell (msfvenom payload →
   multi/handler на Kali → запуск на Windows-жертве → коннект на 4444).
4. Результат: сработало правило **100002, level 12**,
   «reverse shell: соединение на port 4444».

## Значение для защиты

C2-соединение на порт 4444, ранее терявшееся в SIEM, теперь детектируется
как приоритетный алерт. Аналитик увидит reverse shell в момент установки
канала. Правило закрывает конкретный пробел в покрытии детекта.
